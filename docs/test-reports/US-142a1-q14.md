# US-142a1 — waterfall sheet (PC-B, 2026-10-04)

Status: arch-review. Spec: architecture.md 35.1, 35.5, 35.10; Q14 item 5.

Implemented world and placed-level `waterfalls`, validation (8/world, drop 2..20 m), frame conversion and world-definition save/load. Sheets are static ballistic meshes with 0.5 m lip columns and arc rows, stopping at the exact drop. Rendering uses the existing water layer, slots 8..11, both faces, the scene-depth occluder, and arc metres in WATER.z. Frustum rejection precedes selection of the four nearest lip midpoints; tie order follows content order. Sheet-only worlds dispatch both twins.

The packed sheet look reuses surface-only fields without increasing the 56-float row or the uniform budget. Defaults are fallRamp `|:'`, fallSpeed 8 m/s, highlight [235,245,255], sheetAlpha .75. CPU folds the scrolling phase in f64; both composites use salt 61, three brightness levels and unlit foreground highlights above .92. Both sides blend over the scene and preserve behind-scene outlines.

## Implementation notes / handoff

The mesh stores lip-relative XY plus world Z and uses the world lip origin in each slot, rather than absolute f32 XY. This is equivalent world geometry while preserving the existing origin-folding precision rule. Buffers are lazily uploaded once per mesh, matching the clipmap resource lifecycle. No waves, picking, collision, shadow or designer content placement was added. World water point queries remain surface-region queries. Owner-visible waterfall placement/spray/alcove/plunge-pool assets belong to US-142a2 on PC-A.
