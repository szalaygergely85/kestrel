# S8-C-02: active play-time accumulator

2026-10-08, lane C. Per the ARCH queue correction, this completes only the
missing accumulator; US-089a already supplies three slots, metadata and
isolated deletion. No second slot layer or storage format is introduced.

`createPlayTime(savedSeconds = 0)` in saveState.js exposes `seconds` and
`tick(dt, playing)`. The host supplies seconds and a boolean active-play flag.
Only `playing === true` advances time. Resume from save.meta.playTimeSec and
pass clock.seconds to collectSave's existing playTimeSec option. Invalid or
overflowing values throw RangeError before modifying the counter. No browser
globals, allocation in tick, wall-clock dependency or game loop edits.

Tests resume 125.5 seconds, exclude a paused interval, include fractional dt,
interleave 600 paused/active steps and confirm exactly five added seconds
within floating-point tolerance. The result persists through real save
collection/stringification/parsing and a memory slot; another slot and a
separate counter keep their own time. Negative/non-finite/non-number values
and overflow leave the previous time intact.

Owner-visible check: not applicable, pure data helper. NEEDS B1: S8-B1-01
supplies the gameplay pause/menu state and persists clock.seconds with the
save; recommend use the helper in the simulation update, alternative retain
caller-provided playTimeSec until integration. This module does not measure
background or menu time on its own.
