# PERF-01: voxel instances posed once per pass instead of twice (2026-10-16, PC-B, kestrel-1)

## Profile (before, ultra 480x180, CPU profile of the perf-pose spin, % of samples; same order at roadBend/forest/fordDetail)
computeVoxelPose 7.3 + matMul3 4.8-5.5 + buildRot 4.5-5.1 + setRz 3.4-4.0 + setRy 2.8-2.9 + samplePose 1.9 = **~25 % voxel pose**;

Cause: every queued voxel instance was posed (computeVoxelPose) 4x per frame: VoxelPool.project + addVoxelInstances (raster), projectShadow + addVoxelInstances (shadow list).

## Change
- `engine/render/voxelPool.js`: each projected/shadow slot keeps a copy of the FORWARD part transforms of the pose it was just given (`fwd`, `fwdModel`; fixed-size Float64Array per slot, zero per-frame allocation).
- `engine/mesh/voxelMesh.js` `addVoxelInstances`: uses the slot's `fwd` + `pose` (flags) when `fwdModel === model`; anything else (fixtures, plain objects) is posed as before. Same inputs and same code -> bit-identical matrices; 4 poses per instance per frame -> 2.

# PERF-03: sliced + 4x faster collider BVH build, voxel shadow casters pre-culled (2026-10-16, PC-B, kestrel-1)

## Cause
`buildTrunkCollider` (bake-ahead phase 2 of `BandBakeJob`) built its BVH in ONE call: Node probe 24 ms (500 trees) / 59 ms (1500) / 131 ms (3000) / 292 ms (6000); every node sorted its whole range with an Array comparator sort. Point-shadow / sun lists pushed every voxel instance of `shadowView` and culled them afterwards (`DrawList.cull`).

## Change (bit-identical by construction + tests)
- `engine/physics/bvh.js`: new `BvhBuilder` (resumable `step(ms)`, explicit DFS stack = same node indices; quickselect split at `mid` instead of a full sort - the (key, source index) order is strict and total, so the halves are the same; leaf halves insertion-sorted = old leaf order). `buildBvh` = builder.step(Infinity). 3000 trunks 116 -> 30 ms one-call; sliced at 1 ms: max call 3.1 ms (3000 trees) / 5.7 ms (6000; root node + final copy are single units).
- `engine/world/colliders.js`: `ColliderBuildJob` + `trunkColliderJob` / `detailColliderJob` (tris 1 call, builder setup 1 call, then slices); `engine/world/bandBake.js` phases 2-3 step them with the bake budget. The band still swaps only at phase DONE (sync path `_bandJobStep(Infinity)` unchanged), so colliders are complete before the player can stand in the band.
- `engine/mesh/voxelMesh.js` `addVoxelInstances(..., planes)` skips instances whose `rect` is CULL_OUT (same classifyAABB test `DrawList.cull` applies right after); `shadowList.js` passes its planes (sun list and every point slot). Same culled list -> same hash, so slot re-renders do NOT change (only pushes/resetDrawItem/part copies are saved); differs only if a list overflowed capacity (then fewer drops).
- Tests: `engine/physics/bvhBuilder.test.js` (old recursive build as reference, Object.is per element, one-call and 0-ms sliced; trunk job == one-call builder); `voxelMesh.test.js` PERF-03 (pre-culled == pushed-then-culled). `tools/perf-pose.mjs` rows gain cpuP99/cpuMax/frameP99/frameMax/frameOver16/cpuOver8.

# PERF-09: why recipeHeight ran unoptimised + fix (2026-10-16, PC-B, kestrel-1)

## Cause
- Chrome CDP `--cpu-profile`: every recipe node has an EMPTY `deoptReason` (Chrome only fills it for "optimization disabled" functions, not runtime deopts) -> used Node (same V8 path, reproduces it).
- Node `--trace-deopt-verbose` on tools/bench-geo-perf.mjs: recipeHeight deopts **411x**, always "Insufficient type feedback for generic named access" at overworld_far.js:479:25 = `R.ridge.height`.
- `%DebugPrint(recipe.ridge)` after `World.load`: **deprecated_map** (fresh module: not deprecated, 0 deopts). Object literals share V8 maps by property order; `{ height: 1.6, ... }` (World.navFloorProbe opts, double) generalises the Smi `height` field of `ridge: { height: 30, ... }` -> its map is deprecated, the load IC keeps hitting the deprecated map, TurboFan drops deprecated maps from feedback = "insufficient" -> deopt -> re-optimise -> loop. recipeHeight therefore lived in Ignition/Sparkplug and boxed every double.

## Change (byte-identical by construction)
`design/levels/overworld_far.js`: recipeHeight + riverX read their recipe constants (tower, farTower, seed, home, hill2, rolling, valley, ridge, river carve/sine terms) from closure vars snapshotted once at module load (nothing mutates them at runtime; `river.bedLine` stays a live read because tests swap it). Same values, same expression order. `tools/perf-walk.mjs --cpu-raw file.json` dumps the raw CDP profile (dev only).
