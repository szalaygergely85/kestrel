# US-090a title menu view module

2026-10-08, lane C. Implemented PC-A's queue-authorised placeholder menu using
the existing plate [10,11,16] and existing cream foreground. New game,
Continue, three save slots, confirmed delete and Settings work through a
standalone controller/view; it takes the shipped US-089a adapter. No main.js,
game boot, platform storage or engine changes.

New-game slot selection confirms replacement before emitting a request and
retains the old save for the host to replace safely. Continue reads the
selected/first valid slot; clicking a saved slot loads it directly. Slot
labels show name/place/h:mm; empty/corrupt/unavailable slots never emit load.
Delete defaults to Cancel, mutates only the confirmed slot and stays on the
confirmation screen with an error if storage denies it. Keyboard and pointer
input share row actions. Pending host requests are consumed once.

Node checks use the real memory/storage adapters and public UiLayer: metadata
formatting, explicit plate alpha/color, keyboard/mouse actions, empty-slot
selection, cancel/replacement preservation, deletion isolation, consumed
actions, corrupt reads and denied deletes. Draw reuses its layout object and
cached rows/labels; storage reads and formatting happen on input/refresh.

Real headless Chrome, NVIDIA/lovelace WebGPU, scene 400x150/UI 160x60:
inspected `captures/title-menu-main.png` and `captures/title-menu-confirm.png`.
Visible: yes — centred 720 px placeholder panel; cream slot labels, focus
marker and keyboard hints readable on its dark plate. This is a standalone
title-menu preview, not a player-world view. Physical keyboard opened New game
and requested empty slot 2; Delete on that empty slot stayed inert. Selecting
slot 1 then physical mouse confirmation deleted only slot 1, preserving slot 3.
The preview runs the normal continuous presentation loop; both captured
screens include the complete heading, border, labels and keyboard hints.
