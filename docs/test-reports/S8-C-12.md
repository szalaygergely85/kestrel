# S8-C-12: quest objective HUD and log

2026-10-08, lane C. New standalone game/js/ui/questLog.js reads the shipped
quest sim definition/state. update(state) caches a clipped active objective
and completed/active/locked row labels. drawHud(ui,x,y) clears the full HUD
slot before writing, including after the quest completes; drawLog(ui) shows
status markers in a centred plate and returns reused bounds. Formatting and
row allocation stay outside draw calls. Quest state is never modified.

Usage: createQuestLog(def,{hudWidth:60,width:72}); call update(state) after
quest changes, then drawHud/drawLog after clearing the public UiLayer. Read
getObjectiveLine() for a host HUD text slot. snapshot() is diagnostic, outside
the draw path. Foreground/plate reuse existing cream and [10,11,16]; objective
copy comes from existing m1.quest.json placeholders, with no new story text.

Focused Node suite PASS: active/done transitions through the M1 chain,
12-cell ellipsis, explicit opaque plate, repeated draw with reused layout,
unchanged quest data, detached diagnostic snapshot and clearing stale HUD
glyphs after completion. Invalid width/incompatible quest refuses.

Preview: game/js/ui/questLog.preview.html?backend=webgpu (also accepts
?backend=webgl2), memory-only state, Next objective and Reset buttons. Real
NVIDIA/lovelace WebGPU at 400x150/UI 160x60: six physical mouse clicks complete
the chain, HUD cleared, no runtime exceptions. Inspected
captures/quest-log-middle.png: visible yes, cream HUD and completed/active log
markers and objective text clearly readable on the dark placeholder plate.
This is a standalone UI preview, not a player-world view. Probe ports
9870/9871 cleaned up; owner world/platform saves untouched.
