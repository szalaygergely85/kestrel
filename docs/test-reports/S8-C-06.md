## Result and remaining content

createChests is a pure sim module; createLoot now accepts an explicit chest branch for fixed rewards plus one optional weighted pick. The existing boar branch, five-draw RNG contract and corpse behavior are unchanged. Default interaction data in lootConfig matches the supplied chest art: radius 1.6 m, 70 degree facing, front half-plane; writer prompt is [E] Open chest. The simulator takes world-space chest front vectors and player forward vectors, without trigonometry or a render dependency.

Each chest owns a deterministic stream derived from the caller's world seed and its stable id. Rewards are rolled once at create; definition/opening order and full-pack retries cannot reroll another chest. A fixed-only table draws no random values; a weighted table draws once and selects one row. Fixed and selected rewards of the same id merge. Pending-owner items (including cog), touch-only pickups, bad refs/counts/weights and empty tables are rejected before any grant.

Opening grants after 0.6 s of active simulation. Repeat interaction while opening/open is refused. Inventory must have space for the whole reward: no partial grant or lost leftovers. If the pack fills during the animation, the chest returns to closed and retains its rolled reward for retry. Open state is committed before inventory:added/chest:opened events, so event-triggered saves are consistent. The host snapshots openedIds() into the existing collectSave({openedChests}), and passes restored ids into createChests. A save during ungranted opening reloads closed and safely restarts; unknown/unloaded opened ids are retained. No extra save version/layer.

## API

`createChests(defs, {items, inventoryOf, events, openedChests, seed})`

Each def: `{id, x, y, z, frontX, frontY, interact:{radius, facingDeg, facingCos}, table:{fixed:[{item,n}], weighted:[{item,n,weight}]}}`. facingCos is a precomputed field, paired with the authored degree value. Use CHEST_DEFAULTS for the supplied art's values. front is the model local -y transformed to world coordinates by the host; player pose `{x,y,z,forwardX,forwardY}` uses feet/anchor z, not camera eye height.

Methods: stateOf(id), canOpen(id, pose), open(id, pose), step(dtSeconds, playing), openedIds(). canOpen covers the spatial/state gate; open additionally checks pack capacity. Events use reused synchronous payloads; subscribers that retain them must copy. The card should consume inventory:added only after the host commits the chest state. No runtime World interactable or behavior is registered yet.
