# ME-14a — mesh content loading (2026-10-03)

Implementation ready for PC-A architect review, saved locally.

- Mesh schema/envelope and migration table; hierarchical mesh IDs are accepted without relaxing level/world IDs. `loadContentPack` converts mesh content to typed MeshData, validates it, retains material mappings and reports invalid/duplicate files as ContentError.
- AssetRegistry supports mesh access, registration/replacement, and JSON/global merging with duplicate-source rejection.
- glTF CLI accepts `--mats` material-name -> palette-key sidecars, preserves mappings in MeshData/JSON, and writes the mesh content envelope. MeshData serialization preserves optional maps.
- Content validation checks registered mesh geometry/materials, exactly one mesh/level per structure, mesh-only finite yaw, and mesh component references in world/chunk entities. Optional mesh-file scanning is now part of validateContent; the CLI uses it. Unregistered import samples remain geometry-only checks, since their source materials have not been mapped for placement.
- Frame helpers accept a fifth makeFrame argument, yawDeg, for mesh frames; grid frames retain exact quarter-turn behaviour. Nonzero yawSteps cannot combine with yawDeg. Point/direction/yaw/bounds/equality helpers support mesh frames without allocating per call.
