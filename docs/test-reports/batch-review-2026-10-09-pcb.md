## Rulings

- **Q1 (12c second octave `*2.03 + 17` pops at the mod-256 drift wrap; the sky has the same flaw): accept for 12c, then fix in one follow-up story for sky and shadow together.** Cause: the drift `off` jumps by 256 at the wrap. Octave 1 is 256-periodic, so it is continuous; octave 2 jumps by 2.03*256 = 519.68, which is not a multiple of 256. The pop happens once every 256/|wind| seconds (minutes at today's dev wind) and is identical in sky and ground, so they stay consistent. Fix (new row `CLOUD-WRAP-01`, B2): change the octave-2 frequency to exactly `2.0` (keep `+17.0`) in `sky.js` (JS), the sky WGSL/GLSL cloud branch, `cloudShadow.js` and `common.wgsl.js` `cloudShadeQ4`, in one commit. Then 2*256 = 512 is 0 mod 256 and the wrap is seamless. Add a test that `cloudShadeQ` is equal across `off` and `off - 256`. This changes the sky look slightly: owner look, and any gpucompare sky row is re-baselined, never threshold-widened (D-039). Do NOT instead widen the wrap period to 25600 (that loses f32 precision in the offset).
- **Q2 (SWAY shadow key re-renders the 2048^2 sun map at 10 Hz while windy): accept 10 Hz.** While the player moves, `M` already changes every 0.02 m and the map re-renders every frame, so wind only adds cost on standing-still frames, and it is capped at 1/6 of the walking-case cost. Condition: report `shadow` WebGpuTimer p95 with wind on, standing still, in the lane file. If it is above 1.0 ms, add `shadowOpts.swayHz` (default 10; Low preset 0 = sway frozen in the shadow pass, i.e. pack wind with t = 0 and key 0) rather than lowering the global constant. Apply the quantised-time packing from nit 2(a) so the map matches its key.
- **Q3 (ALPHA-01f-fix `meshIsMasked()` because registry MeshData carries `ranges[].mask`, not `maskRanges`): correct.** `maskRanges` exists only on `MeshDrawCache` draw copies built with an atlas. The ONE_PART decision has to be made from the source mesh (`g.mesh` / `lod1Mesh`), which only has `ranges[].mask`.
