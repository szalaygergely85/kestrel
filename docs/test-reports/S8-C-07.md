# S8-C-07 item-get card

## Result

createItemGetCard(adapter,{style,items,rgb,reduceMotion,dev}) uses PC-A's itemGetCard layout, approved item copy, existing palette and icons. Cached item rows/cells at create and count/queue labels at push; no formatting in draw/step. Frame/rivets/title band, icon glow/pulse/sparkles, kind, count/heart-piece progress and guarded continue footer come from the supplied style. Reduce motion keeps a static glow and suppresses sparkles. Pending-owner annotation is dev-only. This UI can preview any definition but grants nothing and writes no saves.

The card holds for 1.5 s, ignores input in the first 0.25 s, fades text/glow in/out using the style timings, and leaves the next card's 0.1 s queue gap paused. The entire queued burst has one pause/unpause; a consumed key is not carried into another card. Late arrivals during fade survive; large dt crosses phases/queued cards deterministically. The plate stays opaque during text fades; no new engine alpha path. Scene dim is exposed through pushDim; per-region background dim needs host integration if desired. The host must keep ticking this presentation controller while gameplay is paused.

API: push(id,n,{count,packFull}), dismiss(), clear(), step(dtSeconds,keyPressed), draw(ui), pushDim(dim), isOpen. snapshot() allocates only for tests/debugging. The optional adapter.setPaused(boolean) is a notification; host pause/input ownership stays outside the view. count is the post-grant pack total; n is the quantity received. push/clear are cold arrival/lifecycle operations. Internal item rows are immutable; frame state/layout is reused.
