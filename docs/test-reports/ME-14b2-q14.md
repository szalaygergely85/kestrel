# ME-14b2 - mesh structures in World (2026-10-03)

Status: arch-review.

World.load resolves structures[].mesh through the asset registry and places MeshData with an arbitrary-yaw Frame and the world AABB of its eight bounding-box corners. Placement bumps structure/render versions and emits the existing placement event. Grid queries, prop/interaction/trigger collection, terrain ring-height helpers, level sun fallback and dynamic-sector operations skip mesh placements. Invalid mesh yaw is rejected by makeFrame rather than silently converted to zero.

Save/load retains only the authored mesh asset ID, origin and yaw; no geometry, AABB, colliders or dynamics are serialized for meshes. Existing level saves preserve their prior shape. Deserialization resolves the asset again and rebuilds the placement and colliders through World.load.

Files: engine/world/World.js, triggers.js, serialize.js and new meshStructures.test.js. Trigger and serialization guards are necessary companion changes: both independently assumed every structure had a level.

Verification: 323 focused checks cover yaw 0/35/90/-20/225, both placement orders, overlapping mesh/grid footprints, AABBs, rotated collider ray hits, dynamic isolation and JSON save round trips. A 600-tick grid-query/sector-step hash stays equal with and without the imported mesh; this checks grid isolation, not mesh rendering. The existing independent core 600-tick replay suite remains 10/10. Full runner 201/201 PASS, no FAIL/TIMEOUT/WARN; check-deps OK (364 files, existing warnings only).

Rendering and renderer structure-list consumers remain ME-14c, which needs PC-A notes. No mesh is placed in shipped gameplay content by this story; no render, main.js or design edits are included.
